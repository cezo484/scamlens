        How it works

        Every screening goes through one of three paths. The badge on each result says which one was used.

        1. Hybrid (Firebase AI Logic). With a Firebase project configured, screening goes through the Firebase AI Logic hybrid SDK in PREFER_ON_DEVICE mode: Gemini Nano screens the message on-device when available, and the SDK falls back to a cloud Gemini model when it is not. The response reports which one actually ran, and the badge shows it.
        2. On-device (direct). Without a Firebase config, Chrome's Prompt API runs Gemini Nano in the browser. The message stays on the device and the screening costs nothing. Needs Chrome on desktop, version 139 or newer, with the on-device model downloaded.
        3. Local. When no model path is available, on-page rules screen the message: known scam patterns plus a link inspector that checks every URL for lookalike domains, punycode, shorteners and other tricks. The demo always works, even with no setup at all.

        The deep explanation is a separate step with its own path: a cloud Gemini model through Firebase AI Logic (ONLY_IN_CLOUD), and only when you tap the button. Without a Firebase config, the explanation is built from the on-page checks instead.

        If a path fails, the next one is tried automatically. The attempt log under the badge records what happened.
